# 临期用卡实施计划

> 执行方式：本聊天直接实施，复用已批准设计，不再重复设计确认。应用 executing-plans、TDD；末尾做一次独立只读复核。

**目标：** 本机按当前账号明确授权，在卡到期前 30 分钟内保守自动兑换。

**架构：** 新增 `expiring_reset.rs` 管理独立持久化授权与执行记录；现有 quota worker 提供 RPC 会话。原生菜单沿用右侧勾选；悬停显示状态和最近结果，首次开启使用明确账号授权对话框。

**技术：** Rust、serde、现有 Windows API 和文件互斥，不新增依赖。

**设计：** `docs/superpowers/specs/2026-10-30-expiring-reset-design.md`。

## 约束

- 默认关闭；无 auth.json、wham、云托管、真实卡测试。
- 显式 creditId、原请求幂等键、发送前落盘、账号及计划复核、本机跨进程互斥。
- 原目标到期前禁止换卡，包含成功、noCredit、目标消失、开关切换和重启。
- 未知结果仅在约 60/300 秒恢复两次，不能确认则暂停；关闭阻止新写请求。
- 保留红点、到期时间、开机启动、检查更新和 v0.3.6 重叠修正；移除旧临期系统弹窗及其开关。
- 不停止、安装、推送或发布；当前交付统一为 v0.3.5，使用新产物目录，保留历史候选。

## 复核重点

- 账号/计划变化在二次读取或确认期间发生，禁止借用旧许可。
- 发出后断线/崩溃，重启恢复原卡原键，持久化失败禁止发送。
- 两张同时临期，成功但额度旧、卡消失、跨实例或切换开关都不能换卡。
- 关闭与请求在途竞态；无桌面窗口只保留 worker，不创建 WebView。
- Windows 未显示通知时，悬停仍可查看结果；日志不得包含账号、卡 ID 和请求键。
